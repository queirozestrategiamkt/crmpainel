01 O que você tem hoje — e o que falta
🏠
Imagine que você tem a maquete de uma casa. Ela é linda, tem janelas, portas, cômodos, tudo. Mas ainda é só papel e plástico — ninguém pode morar nela. O CRM que você tem agora é exatamente isso: a maquete perfeita. Precisamos construir a casa de verdade.
O que é o arquivo HTML que você tem

É como um desenho muito bonito de um painel. Todos os números, gráficos e tabelas que você vê são inventados dentro do próprio arquivo. Se você deletar um lead, ele desaparece quando você fecha o navegador. Se você adicionar um cliente, ele some na próxima vez que abrir.

Isso se chama "dados mockados" — dados de mentira só para mostrar como vai ficar. É normal e necessário no início do desenvolvimento.

O que precisa ser construído

Para funcionar de verdade, precisamos de 3 coisas, como em qualquer sistema:

1. Um banco de dadosOnde as informações ficam salvas
2. Um servidor (backend)O "cérebro" que conecta tudo
3. Uma hospedagemOnde o sistema fica na internet
🧠
Analogia simples: Pensa num restaurante. O HTML é o cardápio bonito. O banco de dados é a cozinha com os ingredientes. O servidor é o garçom que vai e volta entre os dois. A hospedagem é o prédio onde o restaurante funciona.

O Supabase te dá uma URL + chave secreta. Você coloca essa chave no CRM e pronto — o sistema passa a salvar e buscar dados reais em vez dos dados inventados.

03 Hospedagem — onde o sistema fica na internet
🏢
Hospedagem é como alugar um espaço na internet. É um computador que fica ligado 24h por dia no mundo, guardando seu sistema. Quando alguém acessa "lexflow.queirozestrategia.com.br", esse computador entrega o site para o visitante.

04 Segurança — nível profissional explicado
🔐
Segurança é como a proteção de uma casa. Você tem a tranca da porta (login com senha), câmeras (log de acessos), cofre (criptografia), seguro (backup), e um porteiro eletrônico (2FA). Cada camada protege de um tipo diferente de invasão.

Avaliação honesta do sistema atual:

⚠
Nível atual: BAIXO-MÉDIO (apenas para demo)
O HTML que você tem agora tem login com usuário e senha, mas a senha está visível dentro do próprio código. Qualquer pessoa que abrir o arquivo HTML vê pass:'Joaquim.123@1'. Isso NÃO é seguro para dados reais. Precisa ser substituído por autenticação real antes de usar com dados reais.
✓
Nível após implementação com Supabase: ALTO
O Supabase inclui automaticamente: autenticação segura com hash de senha (bcrypt), tokens JWT com expiração, HTTPS em todas as conexões, Row Level Security (cada usuário só vê seus dados), e proteção contra SQL Injection por padrão.

Camadas de segurança que você vai ter

1
Autenticação — "Quem é você?"
O Supabase Auth faz isso por você automaticamente. Cada usuário tem email + senha com hash bcrypt (não dá pra descobrir a senha original, mesmo que invadam o banco). Você pode ativar também o 2FA (dupla verificação) — igual ao banco: você digita a senha e depois um código que vai pro seu celular.
2
Criptografia AES-256 — "Mesmo que roubem, não entendem"
O Supabase criptografa todos os dados em repouso com AES-256 (o mesmo padrão usado por bancos e governos). Se alguém invadir fisicamente o servidor e pegar o HD, os dados aparecem como código ilegível. A chave para descriptografar só existe no sistema autorizado.
3
HTTPS / TLS — "Os dados viajam em um túnel secreto"
Todo dado que sai do seu computador até o servidor viaja criptografado pelo TLS. Se alguém interceptar a conexão (ataque man-in-the-middle), só vê lixo ilegível. O Vercel e Railway configuram isso automaticamente — você não precisa fazer nada.
4
Row Level Security (RLS) — "Cada um vê só o que é seu"
O Supabase tem um recurso chamado RLS. Você define regras: "o usuário X só pode ver os leads da empresa X". Isso impede que um funcionário acesse dados de outro cliente mesmo que descubra a URL da API.
5
Backup automático + WAL Recovery
O Supabase faz backup diário automático. Mas melhor ainda: ele usa WAL (Write-Ahead Log) — isso significa que se o banco "morrer" agora às 14h32, você pode restaurar para o estado exato de 14h31. É como um "Ctrl+Z" com data e hora precisos. Muito mais seguro que backup diário simples.
6
Proteção contra ataques comuns
Brute Force: bloqueio automático após X tentativas de login erradas
SQL Injection: o Supabase usa queries parametrizadas — impossível injetar código malicioso
XSS: Vercel tem headers de segurança que bloqueiam scripts maliciosos
DDOS: Vercel e Railway têm proteção nativa de CDN contra ataques de volume
🚨
NUNCA faça isso: Não coloque a chave secreta do Supabase (service_role key) dentro do HTML que vai pro ar. Essa chave dá acesso total ao banco. Use apenas a chave pública (anon key) no frontend, e a chave secreta só no backend (Railway/n8n).
✓
Resumindo a segurança pós-implementação: Com Supabase + Vercel + Railway, você vai ter segurança de nível empresarial sem pagar por isso. É o mesmo padrão técnico que startups como Notion, Linear e Vercel usam para guardar dados de milhões de usuários.
05 Integração das APIs — como conectar o mundo real
🔌
API é como uma tomada padronizada. Cada serviço (Google, Instagram, Meta) tem uma tomada específica. Você precisa do "plug" certo para cada uma. Esse plug é chamado de API Key ou Token — é uma senha longa que prova que você tem permissão para pegar os dados daquele serviço.
API 1 — Google Sheets (sincronização de planilhas)

Para que serve: Quando você atualizar uma planilha Google, o CRM atualiza automaticamente. Quando o agente IA cadastrar um lead, ele aparece na planilha também.

Como pegar:

// PASSO 1: Criar projeto no Google Cloud 1. Acesse: console.cloud.google.com 2. Clique em "Criar Projeto" → dê qualquer nome 3. No menu lateral: "APIs e Serviços" → "Biblioteca" 4. Procure e ative: "Google Sheets API" 5. Vá em "Credenciais" → "Criar Credencial" → "Conta de Serviço" 6. Dê permissão "Editor" → Baixe o arquivo JSON gerado // Esse JSON é sua chave. Guarde com segurança.

Custo: GRÁTIS até 300 requisições/minuto

API 2 — Google Ads (métricas de campanha)

Para que serve: Busca automaticamente leads, CPL, CTR, gasto real das campanhas Google Ads dos seus clientes.

Como pegar:

1. Acesse: ads.google.com/home/tools/api-center 2. Clique em "Solicitar acesso à API" 3. Preencha o formulário (nome, empresa, uso previsto) 4. Aguarde aprovação (1-3 dias úteis) 5. Depois de aprovado: Google Cloud → Ative "Google Ads API" 6. Configure OAuth2 → Gere Client ID + Client Secret 7. Configure no n8n com as credenciais geradas // Para acessar dados de cliente: peça que ele adicione // sua conta como "Usuário" na conta de anúncios dele

Custo: GRÁTIS — taxa por operação, mas dentro do uso normal é zero

API 3 — Instagram / Meta (engajamento e ads)

Para que serve: Pega seguidores, posts, alcance e dados de campanhas do Meta Ads (Facebook + Instagram).

1. Acesse: developers.facebook.com 2. "Criar App" → Tipo: "Business" 3. Adicione o produto: "Instagram Graph API" 4. Configure Basic Settings: nome, email, política de privacidade 5. Gere o User Access Token (tem validade de 60 dias) 6. Converta para Long-Lived Token (válido por 90 dias) 7. Configure renovação automática no n8n // Para dados de cliente: peça que ele conecte a conta // profissional do Instagram ao seu Business Manager

Custo: GRÁTIS para leitura básica de dados

06 Passo a passo completo — do zero ao funcionando
🗺️
Pense nisto como montar um IKEA. Tem muitas peças, mas cada passo é simples se você fizer um de cada vez. Não tente fazer tudo de uma vez — siga a ordem abaixo.

Fase 1 — Configurar o banco de dados (1-2 horas)

1
Criar conta no Supabase
1. Acesse supabase.com
2. Clique em "Start your project" → entre com sua conta Google
3. Clique em "New Project" → dê o nome "lexflow-crm"
4. Escolha uma senha forte para o banco (guarde ela!)
5. Região: South America (São Paulo) — mais rápido para você
6. Aguarde ~2 minutos para o projeto criar
2
Criar as tabelas no Supabase (painel visual — sem código)
No painel do Supabase, clique em "Table Editor" no menu lateral. Crie as seguintes tabelas clicando em "New Table":

Tabela: leads — colunas: id, nome, escritorio, area, canal, etapa, score, entrada, proximo_passo
Tabela: clientes — colunas: id, nome, area, ticket, meses, nps, cs, checkin
Tabela: campanhas — colunas: id, cliente_id, plataforma, leads_mes, cpl, ctr, gasto, orcamento
Tabela: drafts — colunas: id, tipo, dados (JSON), label, deletado_em, expira_em

Para cada coluna, o Supabase mostra um formulário simples — escolha o tipo (text, number, date, etc.) sem precisar escrever código SQL.
3
Pegar a chave de conexão do Supabase
No painel do Supabase:
1. Vá em Settings → API
2. Copie a Project URL (parece com: https://xyzxyz.supabase.co)
3. Copie a anon/public key (chave longa — começa com "eyJ...")

Guarde esses dois valores — vamos usá-los no próximo passo.
4
Conectar o CRM ao Supabase
Abra o arquivo crm-advocacia-lexflow.html num editor de texto (pode ser o Bloco de Notas). Adicione no início do <script>:
Adicionar no início do JavaScript do CRM
// Cole isso no início da tag <script> do CRM: const SUPABASE_URL = 'https://SEU-ID.supabase.co'; const SUPABASE_KEY = 'eyJ...sua-chave-anon...'; // Importar biblioteca do Supabase (adicione no <head>): // <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script> const { createClient } = supabase; const db = createClient(SUPABASE_URL, SUPABASE_KEY); // Exemplo: buscar leads reais (substitui DATA.leads inventados) async function fetchLeads() { const { data, error } = await db .from('leads') .select('*') .order('created_at', { ascending: false }); if (!error) DATA.leads = data; } // Exemplo: salvar lead real async function saveLead(lead) { const { data, error } = await db .from('leads') .insert([lead]); if (!error) toast('Lead salvo!', 'success'); }

Fase 2 — Colocar na internet com Vercel (30 minutos)

5
Criar conta no GitHub (necessário para Vercel)
1. Acesse github.com → "Sign up" com seu email
2. Crie um repositório novo: clique em "+" → "New repository"
3. Nome: lexflow-crm → marque "Public" → "Create repository"
4. Na página do repositório, clique em "uploading an existing file"
5. Arraste o arquivo crm-advocacia-lexflow.html → "Commit changes"

Pronto — seu código está no GitHub. É como salvar na nuvem com controle de versão.
6
Fazer deploy no Vercel (publicar na internet)
1. Acesse vercel.com → "Continue with GitHub"
2. Clique em "Add New → Project"
3. Selecione o repositório "lexflow-crm"
4. Clique em "Deploy" — aguarde ~1 minuto
5. Vercel vai te dar uma URL tipo: lexflow-crm.vercel.app

Pronto! Seu CRM já está na internet. Qualquer alteração que você fizer no GitHub aparece automaticamente no Vercel em segundos.
7
Configurar domínio próprio (opcional, mas recomendado)
Se você comprar o domínio queirozestrategia.com.br no Registro.br:
1. No Vercel → seu projeto → "Settings" → "Domains"
2. Digite seu domínio e clique "Add"
3. O Vercel mostra os registros DNS que você precisa configurar
4. No painel do Registro.br, adicione esses registros
5. Aguarde até 48h para propagar — geralmente menos de 1h

Fase 3 — Conectar planilhas com n8n (2-4 horas)

8
Criar conta no n8n Cloud
1. Acesse n8n.io → "Get Started for free"
2. Crie conta com email → escolha plano "Free"
3. Você vai ter um painel visual com blocos

Pense no n8n como um "Zapier brasileiro" — você conecta serviços sem código, arrastando blocos.
9
Criar o fluxo: Google Sheets → Supabase
No n8n, clique em "New Workflow" e monte este fluxo:

Bloco 1: "Google Sheets Trigger" → configurar sua planilha de leads
Bloco 2: "Supabase" → "Upsert" → tabela "leads"
Bloco 3: "HTTP Request" → URL do seu CRM (para forçar atualização)

Salve e ative o workflow. Agora toda vez que você editar a planilha, o banco atualiza em segundos.
10
Criar o fluxo: Supabase → Google Sheets (bidirecional)
Agora o caminho inverso — quando alguém adiciona um lead no CRM, aparece na planilha:

Bloco 1: "Webhook" (URL que o CRM vai chamar ao salvar lead)
Bloco 2: "Google Sheets" → "Append Row" → sua planilha de leads

Cole a URL do Webhook no CRM onde você tem a função saveLead().

Fase 4 — Autenticação real (substituir login do HTML)

11
Ativar Supabase Auth
No painel do Supabase → "Authentication" → "Users" → "Add User"
Crie o usuário: queirozestrategia@suaemail.com com a senha desejada.

No CRM, substitua a função doAdminLogin() por:
async function doAdminLogin() { const email = document.getElementById('admin-user').value; const password = document.getElementById('admin-pass').value; const { data, error } = await db.auth.signInWithPassword({ email, password }); if (error) { document.getElementById('admin-err').style.display = 'block'; return; } // Login bem sucedido — carregar dados reais document.getElementById('admin-overlay').classList.remove('open'); document.getElementById('app').style.display = 'flex'; await fetchLeads(); // busca dados reais do banco await fetchClientes(); renderDashboard(); toast('Bem-vindo ao LexFlow!', 'success'); }
✓
Com isso, a senha fica apenas no Supabase (com hash bcrypt). Ninguém pode ver olhando o código HTML. Se alguém tentar 10 senhas erradas, a conta bloqueia automaticamente.

Resposta direta às suas perguntas

O CRM tem dados reais? Não ainda — os dados são mockados (inventados). Você implementa dados reais conectando ao Supabase conforme o passo 4 deste guia.

Como implementar? Siga os 11 passos da Fase 1-4. O mais difícil é a primeira vez — depois fica fácil de manter.

Nível de segurança do banco? Com Supabase, é alto — AES-256, TLS, backup WAL, autenticação bcrypt, proteção SQL injection. Muito acima de uma hospedagem compartilhada comum.

Como integrar as APIs? Via n8n (visual, sem código) ou via JavaScript direto no CRM para as mais simples como Supabase e Google Sheets.

Devo usar a Hostinger? Para o CRM, não é a melhor escolha. Vercel (grátis) + Supabase (grátis) é superior em todos os aspectos técnicos e mais barato.

Como gerenciar informações internas? Tudo fica no Supabase. Você acessa pelo painel visual em supabase.com, vê os dados como uma planilha, edita manualmente se precisar, e o CRM sincroniza automaticamente.
